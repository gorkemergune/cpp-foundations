1. Problem statement

A wallet application stores the change of a user's balance for each day: a deposit is a positive number, a payment is a negative number, a quiet day is 0. The balance starts at 0. The app needs the balance at the end of every day to draw a chart.

Write runningTotals. It receives the daily changes in a std::vector<int> and returns a new vector of the same length whose element i is the sum of the changes from day 0 to day i, both included.

Example scenario. The changes for four days are {3, -1, 4, 0}. After day 0 the balance is 3, after day 1 it is 2, after day 2 it is 6 and after day 3 it is still 6. The function returns {3, 2, 6, 6}.

Lab rules
  • Do not include <numeric> (std::accumulate, std::partial_sum) in L01-A and L01-M. The loop is the exercise.
  • Return a vector with exactly changes.size() elements. Do not print anything; the tests read the return value.

Input, output, constraints

Inputchanges: 0 <= n <= 104 integers, each -104 <= changes[i] <= 104 (every total fits in int).
Return valuea vector r with r.size() == n and r[i] = changes[0] + … + changes[i]. For n = 0 return an empty vector.
ComplexityO(n) time. Do not re-add the prefix for every i (that would be O(n2)).

Sık hata: hem boyut ver hem push_back yap

vector<int> r(n); vektörü n tane 0 ile başlatır. Arkasından push_back yaparsan sonuç 2n uzunlukta olur ve ilk yarısı sıfırdır. İki yoldan birini seç. Ya r(n) kurup r[i] = total yaz, ya da boş r kurup push_back yap.

L01-M · runningTotals

{{ code("sol:lab01.cpp", "runningTotals", title="runningTotals") }}
  • int total = 0; Önceki günlerin toplamını taşıyan değişken bu. Her adımda yalnızca bugünkü değişimi ekliyoruz. Bu yüzden toplam süre O(n).
  • size_t i changes.size() ile aynı türde. -Wall işaretli ve işaretsiz karşılaştırma uyarısı vermez.
  • result.push_back(total) Sonuç her adımda bir büyür. Döngü bitince result.size() == changes.size().
  • return result; Vektörü değerle döndürmek C++’ta normaldir. Derleyici kopyalamak yerine taşır. Pointer ya da new gerekmez.

Neden bu yolu seçtik?

  • İzinli işlemler. Yalnızca size, [] ve push_back kullandık. <numeric> yasak olduğu için toplamı elle taşıdık.
  • Sıra. Sonuçta i. eleman i. günün bakiyesi. Döngü soldan sağa gittiği ve sona eklediği için sıra kendiliğinden korunuyor.
  • Maliyet. Zaman O(n). Ek bellek sonuç vektörü için O(n). Parametre değerle geldiği için çağrı anında bir O(n) kopya daha oluşuyor. Lab 02’de const& ile bu kopyayı kaldıracağız.

L01-X · neden “sabit n” gerekiyor?

{{ snippet(''' // WRONG: undefined behaviour for (int x : nums) { nums.push_back(x); // the vector grows while range-for is walking it } ''', title="Hatalı") }} {{ code("sol:lab01.cpp", "getConcatenation", title="Doğru") }}

Range-for, vektörün iç belleğini gösteren iterator’larla dolaşır. push_back kapasiteyi aşınca vektör yeni bir yere taşınır ve iterator’lar geçersiz kalır. Sonuç çökme, sonsuz döngü ya da rastgele değerler olabilir. Doğru sürüm, başlangıç boyutunu bir kez n’ye kaydedip indeksle çalışıyor.
