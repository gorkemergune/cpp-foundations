1. Problem statement

A music player keeps the current playlist as a std::vector<int> of song IDs. The user can remove the song at a position and insert a song at a position. The playlist object is owned by the caller, so your functions must change the caller's vector, not a copy of it.

The lab restricts you to the operations a fixed-size array would also have, plus one slot added or removed at the end. You therefore have to shift elements yourself. This is exactly what erase and insert do inside the library, and it is the core move of every array-based data structure in this course (array stack, circular queue, heap).

Example scenario. The playlist is {4, 7, 2, 9}. removeAt(v, 1) removes song 7 and the playlist becomes {4, 2, 9}. Then insertAt(v, 1, 7) puts it back: {4, 7, 2, 9}. removeAt(v, 4) returns false because there is no position 4, and the playlist does not change.

std::vector<int>& v is a reference: v is another name for the caller's vector. No copy is made and every change is visible to the caller. const std::vector<int>& (L02-B) is also a reference without a copy, but the compiler rejects any change through it.

Lab rules
  • Work on v itself. Do not build a second vector and copy it back.
  • For an invalid index return false and leave v exactly as it was (same elements, same size).
  • removeAt: valid indexes are 0 … size−1. insertAt: valid indexes are 0 … size; index == size appends.

Input, output, constraints

Input0 <= v.size() <= 104; index is any int (it may be negative or too large); value is any int.
Outputreturn value true/false and the caller's vector after the call. Nothing is printed.
ComplexityO(n − index) element moves, O(1) extra memory.

5. Worked example

removeAt({4, 7, 2, 9}, 1): the index is valid (0 <= 1 < 4). Copy every element after position 1 one step to the left: v[1] = v[2] → {4, 2, 2, 9}, v[2] = v[3] → {4, 2, 9, 9}. The last slot is now a duplicate; pop_back() → {4, 2, 9}. Return true.

insertAt({4, 2, 9}, 1, 7): valid (0 <= 1 <= 3). First make room: push_back(7) → {4, 2, 9, 7}. Then copy right, starting from the back: v[3] = v[2] → {4, 2, 9, 9}, v[2] = v[1] → {4, 2, 2, 9}. Finally v[1] = 7 → {4, 7, 2, 9}. Return true.

Testler hem dönüş değerini hem çağrıdan sonraki vektörü kontrol ediyor.

Lab, erase ve insert kullanmanı yasaklıyor. Kaydırmayı sen yazacaksın. Dizi tabanlı stack, circular queue ve heap’te aynı kaydırma ve indeks mantığını tekrar kullanacağız.

L02-M1 · removeAt

{{ code("sol:lab02.cpp", "removeAt", title="removeAt") }}
  • Önce doğrula. index < 0 || index >= n ise vektöre hiç dokunmadan false dönüyoruz. Boş vektörde n = 0 olduğundan her indeks geçersiz sayılır.
  • int n = v.size(); Boyutu bir kez int olarak alıyoruz. v.size() - 1 boş vektörde 0’dan küçük olmaz, çok büyük bir sayıya döner (Lab 03’te göreceksin). n - 1 ise güvenli.
  • Sola kaydırma ileri yürür. v[i] = v[i + 1] yazarken v[i + 1] henüz değişmemiştir, bu yüzden hiçbir değer kaybolmaz.
  • pop_back() sondaki kopyayı atar. Dönüş tipi void olduğu için int x = v.pop_back(); derlenmez. Önce back() ile oku, sonra pop_back() ile sil. Stack ve queue haftalarında aynı ayrımı top()/pop() ve front()/pop() çiftlerinde göreceksin.

L02-M2 · insertAt

{{ code("sol:lab02.cpp", "insertAt", title="insertAt") }}
  • index > n geçersiz, index == n geçerli. Sona ekleme de bir eklemedir. removeAt’teki koşulla farkı tek karakter: >= yerine >.
  • push_back(value) yer açmanın en güvenli yolu. push_back(v.back()) yazsaydık boş vektörde back() tanımsız davranış olurdu. index == n iken döngü hiç çalışmaz ve değer zaten doğru yerdedir.
  • Sağa kaydırma geriye yürür. i = n’den başlayıp index + 1’e kadar iniyoruz.

Neden bu yolu seçtik?

  • İzinli fonksiyonlar. size, [], push_back ve pop_back. Hepsi vektörün sonunu değiştirir. Ortadaki her değişikliği kaydırmayla yaptık.
  • Korunan sıra. Silinen ve eklenen eleman dışındaki elemanların göreli sırası değişmiyor. Testlerdeki erase/insert karşılaştırması bunu kontrol ediyor.
  • Maliyet. Kaydırma n − index adım sürer. En kötü durum index = 0 için O(n), sondaki işlem için O(1). Ek bellek O(1). push_back nadiren yeniden yer ayırabilir. Ortalamada yine O(1).
  • Geçersiz girdi. Kontrol en başta yapıldığı için yanlış indeks vektörü yarı değişmiş bırakamaz.
