1. Problem statement

Two sensors produce sorted logs of event timestamps. The analysis tool needs three operations on sorted data, all in linear time — sorting again would cost O(n log n) and is not allowed.

  1. Part A — mergeInto. Merge two sorted C arrays into a third array out and return the number of values written. On equal values, take the one from a first.
  2. Part B — merge (LeetCode 88). nums1 has room for both logs: its first m values are real, the last n are placeholders. Merge nums2 into nums1 in place, without a third array.
  3. Part C — intersectSorted. Write the timestamps seen by both sensors into out, each value once, ascending; return how many.

Example scenario. a = {1, 4, 9}, b = {2, 4}: merge gives {1, 2, 4, 4, 9}, intersection gives {4}.

{{ code("sol:lab08.cpp", "intersectSorted", title="Part C — intersectSorted") }}

Eşitlikte iki indeksi birlikte ilerletiyoruz. out[k - 1] != a[i] kontrolü tekrarı engelliyor. Çıktı sıralı olduğu için yalnızca son yazılan değere bakmak yetiyor.

Neden bu yolu seçtik?

  • İzinler. Hiçbir parçada sıralama yok. Girdi zaten sıralı.
  • Korunan sıra. A eşitlikte kararlı, C artan sırada ve tekrarsız.
  • Maliyet. Üçü de O(n + m) zaman. A ve C’de out çağıranın belleği, B’de ek bellek O(1).

Alternatif

B için “nums2’yi nums1’in sonuna kopyala, sonra std::sort” iki satırlık bir çözüm. O((m+n) log(m+n)) sürer ve “<algorithm> yok” kuralını ihlal eder. Sınavda “in place, linear” yazıyorsa puan kaybettirir.
