1. Problem statement

A grading tool reads its input as text. M1: one line holds space-separated integers; return the smallest one through a reference parameter, using the classic “put the first number into a temporary, then compare every next number with it” loop. A line without numbers has no answer: return false and leave out unchanged.

M2: the input stream starts with a line holding a count n; then come n lines of free text (a line may be empty or have extra spaces). Return how many words each of those lines contains. This is the classic cin >> n + getline trap.

Example scenario. minToken("12 -3 5 -3", out) returns true with out = -3. For the stream "3\nhello world\n\n a b c \n", wordsPerLine returns {2, 0, 3}.

Soru ne istiyor?

M1 vize notundaki soru: satırdaki ilk sayıyı geçici bir değişkene (temp) al, sonraki her sayıyla karşılaştır, küçükse temp’i güncelle. Satırda sayı yoksa false dön. out’a hiç dokunma (test 777 koyup bakıyor). Notta yazmayan kural bu kampta şöyle belirlendi: satırda yalnızca geçerli tam sayılar ve boşluklar var.

M2 C++’ın en çok şaşırtan giriş tuzağı. cin >> n sayıyı okur ve satır sonunu akışta bırakır. Hemen ardından gelen getline o boş kalan satır sonunu okur. Python’daki input() her zaman bir satırın tamamını okuduğu için Python’da bu sorun yok.

Çözmeden önce kendine sor
  1. temp’i 0 ile ya da INT_MAX ile başlatmak yerine neden ilk sayıyla başlatıyoruz? Satır boşsa ne olur?
  2. in >> x başarısız olduğunda x’in değerine güvenebilir miyim?
  3. M2’de >> ile getline arasındaki satır sonunu kim tüketiyor?
