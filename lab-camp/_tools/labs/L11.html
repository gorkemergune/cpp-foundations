1. Problem statement

A small bank keeps accounts as objects of class BankAccount. The header (bankaccount.h) is fixed: it declares the data members and the member functions. You write bankaccount.cpp, which defines them. An account never goes below zero, every successful deposit or withdrawal counts as one transaction, and rejected operations change nothing.

Finally write the free function transfer: it moves money between two accounts all or nothing — if the withdrawal fails, the target account must not change either.

Example scenario. BankAccount ada("Ada", 1000), bob("Bob", 0); transfer(ada, bob, 300) returns true: Ada has 700, Bob 300, each has 1 transaction. transfer(ada, bob, 701) returns false and nothing changes.

BankAccount:: says “this is the member declared in the class”. Forgetting it defines an unrelated free function, and the linker then reports an undefined reference to the member.

Rules

Constructorinitialise every member in the initializer list; negative start → 0
Getterskeep the const at the end of the definition too (it is part of the signature)
Rejected operationreturns false, balance and transaction count unchanged
transferuse only the public member functions (from.balance_ is private); the same account on both sides → false

Referans çözüm

  • Initializer list (: owner_(owner), …) üyeleri gövde çalışmadan önce kurar. Gövdede atama yapmak da çalışır, ama önce varsayılan bir değerle kurup sonra üzerine yazar. const veya referans üyeler yalnızca initializer list ile başlatılabilir.
  • Sıra. Üyeler sınıfta bildirildikleri sırayla kurulur, listede yazdığın sırayla değil. -Wall sıralar farklıysa uyarı verir.

  • Önce çek, sonra yatır. Çekme başarısız olursa hiçbir şey değişmemiştir. Yatırma bu noktada başarısız olamaz, çünkü cents > 0 çekme tarafından zaten kontrol edildi.
  • &from == &to iki referansın aynı nesneyi gösterip göstermediğini adres karşılaştırarak kontrol ediyor.
  • Yalnızca public arayüz. transfer sınıfın üyesi değil, bu yüzden balance_’e erişemez. Kuralları (cents <= 0, bakiye) tekrar yazmak yerine withdraw’a bırakıyor.

Neden bu yolu seçtik?

  • Kapsülleme. Bakiye yalnızca üye fonksiyonlar üzerinden değişiyor, bu yüzden “negatif olmaz” kuralı tek bir yerde korunuyor.
  • Maliyet. Her işlem O(1).
