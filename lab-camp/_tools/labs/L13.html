1. Why a paper lab

Every linked-structure question in this course — list, stack, queue, tree, graph adjacency list — is about which arrow points where after each line. Most crashes in timed labs come from one wrong arrow. Professional programmers draw these diagrams too. This lab trains the habit: draw first, code second.

Draw every node as a box with two parts [value | next], and every pointer variable (head, p, q) as a name with an arrow to the box it points to. nullptr is an arrow to nothing. When a node is deleted, cross it out — any arrow still pointing at it is now a dangling pointer.

Node*& head is a reference to the caller's pointer variable: setting head = nullptr inside changes the caller's head. With a plain Node* head the caller would keep a dangling pointer.

Cevaplar
  1. Yeni düğümün next’i eski head->next’i almalı. Önce head->next’i değiştirseydin 3’ün adresini hiçbir değişken tutmazdı. Düğüm erişilemez olur ve bellek sızardı.
  2. Evet. Listeden çıkarmak (unlink) ile silmek (delete) ayrı işlemler. Labwork ve vize sorularında ikisi de istenir.
  3. delete head sonrasında head->next’i okumak silinmiş belleğe erişmektir. Program çoğu zaman çalışır gibi görünür, ama bu tanımsız davranış.
