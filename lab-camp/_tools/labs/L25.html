1. Problem statement

The slides' queue never crashes on an empty queue: every operation returns false instead. It has two dequeue overloads — this is a classic exam trap:

callwhat it doesstd::queue equivalent
q.dequeue()removes the front, does not give the value; false if emptyq.pop()
q.dequeue(x)writes the front into x, then removes itx = q.front(); q.pop();
q.getFront(x)writes the front into x, keeps itx = q.front();

M1 (LeetCode 933): a RecentCounter receives request times in increasing order; ping(t) returns how many requests fall in [t − 3000, t]. Keep the times in the slides' Queue; old times leave from the front. The slides' queue has no size().

M2: compare two const Queue& — you cannot dequeue from a const object, so make copies with the copy constructor (Queue copy(a);) and compare those.

Soru ne istiyor?

Stack haftasındaki iki API karşılaştırmasının queue hâli. Ek olarak kopya kurucu var. Ders Queue’sunun kopya kurucusu bütün düğümleri yeniden kuruyor (deep copy), bu yüzden kopyayı boşaltmak orijinali etkilemiyor.

Sınav tuzağı: hangi dequeue?

Eski kampın LLQueue’sunda dequeue() değeri döndürür (Lab 26’da yazacaksın). Ders kodunda dequeue() yalnızca bool döndürür. while (int x = q.dequeue()) gibi bir döngü kamp API’sinde kuyruktaki ilk 0’da durur, ders API’sinde ise değeri hiç vermez. Doğru kalıplar: ders API’sinde while (q.dequeue(x)), kamp API’sinde while (!q.isEmpty()) { x = q.dequeue(); … }, std::queue’da while (!q.empty()) { x = q.front(); q.pop(); … }. B testindeki {0, 0, 5} satırı tam olarak bu hatayı yakalıyor.
