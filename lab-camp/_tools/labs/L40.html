1. Problem statement

A hash table stores a key at the index h(key) computed by a hash function. Two keys with the same index collide; with separate chaining every index holds a list (a chain) of all keys that hash to it (slides 26–27). Search, insertion and deletion only look at one chain, so they take O(1 + α) on average, where the load factor α = n / tableSize.

  • A, B: the two string hash functions of slides 29–30.
  • M1: a chained table of ints. In C++ -3 % 10 is -3, so the bucket is ((x % size) + size) % size.
  • M2, M3: 2021 Assignment 5 — ints and strings of up to 4 characters in one table of 10 buckets. A string is turned into a number ("AAA" → 65 65 65 → 656565) and hashed like an int; every entry also remembers its type, otherwise the int 656565 and the string "AAA" would be the same entry (the archive solution's bug).

Soru ne istiyor?

Hash tablosu bir dizi gibi çalışıyor: anahtarı bir indekse çevirip doğrudan o hücreye gidiyoruz. Çevirme işini hash fonksiyonu yapıyor. Farklı anahtarlar aynı indekse düşebilir (çakışma). Zincirleme yöntemi bunu her hücrede bir liste tutarak çözüyor. Arama yalnızca tek bir zincirde yapıldığı için zincirler kısa kaldıkça işlemler O(1).
