1. Problem statement

With open addressing every key lives in the table itself. If its home slot h1(key) = key % size is taken, the key tries other slots in a fixed order, its probe sequence (A):

methodi-th slot triedslide
linear probing(h1 + i) % size18–20
quadratic probing(h1 + i²) % size21–22
double hashing(h1 + i·h2) % size, h2 = 7 − key % 723–24

A search follows the same sequence and stops at the key or at an empty slot. That is why deletion cannot simply empty a slot (slide 25): a later key whose sequence passed through it would no longer be found. A deleted slot is marked DELETED: a search walks over it, an insertion may reuse it.

Order of work. insert must first check that the key is not already there, so it calls find: write M1 and M2 together (the test of M1 shows “needs L41-M2” until find exists).
